## What are nullable reference types?

**Nullable reference types** (C# 8.0+) reduce `NullReferenceException` risk by making nullability explicit for reference types (`string`, `object`, etc.).

**Key concepts:**

- **`string?`** — explicitly nullable reference type.
- **`string`** — non-nullable by default when the feature is enabled; compiler warns on null assignment or unchecked use.
- **`int?`** — nullable value types existed earlier; `string?` extends the same idea to references.
- **Compiler warnings** — assigning null to non-nullable types or dereferencing nullable types without checks.

**Enable (opt-in):**

```csharp
#nullable enable
```

Or in `.csproj`:

```xml
<Nullable>enable</Nullable>
```

**Example:**

```csharp
#nullable enable

public class Person
{
    public string Name { get; set; }   // Non-nullable
    public string? Address { get; set; } // Nullable
}

public class Program
{
    public static void Main()
    {
        Person person = new Person();
        person.Name = "John";           // Valid
        person.Address = null;          // Valid

        Console.WriteLine(person.Name.Length); // Safe: non-nullable
        if (person.Address != null)
            Console.WriteLine(person.Address.Length); // Safe after check
    }
}
```

**Nullable contexts:**

| Context | Directive | Behavior |
|---------|-----------|----------|
| Enabled | `#nullable enable` | Annotations enforced; warnings on violations |
| Disabled | `#nullable disable` | Pre–C# 8.0 behavior; references implicitly nullable |
| Warnings only | `#nullable warnings` | Warnings without enforcing annotations |

```csharp
#nullable enable
string? nullableString = null;        // Allowed
string nonNullableString = "Hello";
nonNullableString = null;               // Compiler warning

#nullable disable
string oldStyleNullableString = null;   // No warning
```

**Benefits:** fewer runtime null errors, clearer contracts, stronger static analysis.

## Describe pattern matching enhancements in recent C# versions?

Pattern matching (C# 7.0+) makes type checks, switches, and destructuring more expressive.

**C# 7.0 — type patterns and switch patterns:**

```csharp
object obj = "Hello, World!";
if (obj is string s)
    Console.WriteLine(s.Length);

object num = 42;
switch (num)
{
    case int i:
        Console.WriteLine($"Integer: {i}");
        break;
    case string s:
        Console.WriteLine($"String: {s}");
        break;
    default:
        Console.WriteLine("Unknown type");
        break;
}
```

**C# 8.0 — switch expressions, property patterns, positional patterns:**

```csharp
int number = 10;
string result = number switch
{
    0 => "Zero",
    1 => "One",
    _ => "Other"
};

public class Person { public string Name { get; set; } public int Age { get; set; } }
Person person = new Person { Name = "John", Age = 30 };
if (person is { Name: "John", Age: > 20 })
    Console.WriteLine("John is over 20 years old.");

public class Point
{
    public int X { get; }
    public int Y { get; }
    public void Deconstruct(out int x, out int y) => (x, y) = (X, Y);
}
Point point = new Point(3, 4);
var message = point switch
{
    (0, 0) => "Origin",
    (var x, var y) when x == y => "Diagonal",
    _ => "Some other point"
};
```

**C# 9.0 — relational and logical patterns (`and`, `or`, `not`):**

```csharp
int age = 25;
var category = age switch
{
    < 13 => "Child",
    >= 13 and < 20 => "Teenager",
    >= 20 and < 65 => "Adult",
    _ => "Senior"
};

int n = 15;
var bucket = n switch
{
    > 0 and <= 10 => "Between 1 and 10",
    > 10 and <= 20 => "Between 11 and 20",
    _ => "Other"
};

object obj = "hello";
if (obj is not null)
    Console.WriteLine("Object is not null");
```

**C# 10.0 — constant and parenthesized patterns:**

```csharp
int number = 10;
string msg = number switch { 10 => "Ten", 20 => "Twenty", _ => "Other" };

int n = 5;
var result = n switch
{
    (>= 1 and <= 10) => "Between 1 and 10",
    _ => "Other"
};
```

**C# 11.0 — list patterns; required members:**

```csharp
int[] numbers = { 1, 2, 3 };
var listResult = numbers switch
{
    [1, 2, 3] => "Exact match",
    [1, 2, ..] => "Starts with 1 and 2",
    _ => "No match"
};

public class Person
{
    public required string Name { get; init; }
    public required int Age { get; init; }
}
```

**Version summary:** C# 7 — `is`, switch patterns; 8 — switch expressions, property/positional; 9 — relational/logical; 10 — constants, parentheses; 11 — list patterns, `required`.

## What are asynchronous streams (IAsyncEnumerable)?

**`IAsyncEnumerable<T>`** (C# 8.0+) iterates collections asynchronously — ideal for paginated APIs, streaming I/O, DB results, and real-time data.

**Key points:**

- Unlike synchronous `IEnumerable<T>`, items are produced/consumed with `await foreach`.
- Use `yield return` with `await` inside `async IAsyncEnumerable<T>` methods.
- Lazy fetching — process items as they arrive; does not block threads during I/O.
- Supports `CancellationToken`; LINQ-style operators via `System.Linq.Async` (`Where`, `Select`, etc.).

**Basic usage:**

```csharp
public class AsyncStreamExample
{
    public async IAsyncEnumerable<int> GetNumbersAsync()
    {
        for (int i = 1; i <= 5; i++)
        {
            await Task.Delay(1000);
            yield return i;
        }
    }
}

public class Program
{
    public static async Task Main()
    {
        var example = new AsyncStreamExample();
        await foreach (int number in example.GetNumbersAsync())
            Console.WriteLine(number);
    }
}
```

**With cancellation:**

```csharp
public class AsyncStreamWithCancellation
{
    public async IAsyncEnumerable<int> GetNumbersAsync(CancellationToken cancellationToken)
    {
        for (int i = 1; i <= 5; i++)
        {
            await Task.Delay(1000, cancellationToken);
            yield return i;
            if (cancellationToken.IsCancellationRequested)
                yield break;
        }
    }
}

public class Program
{
    public static async Task Main()
    {
        var example = new AsyncStreamWithCancellation();
        var cts = new CancellationTokenSource();
        cts.CancelAfter(3000);
        try
        {
            await foreach (int number in example.GetNumbersAsync(cts.Token))
                Console.WriteLine(number);
        }
        catch (OperationCanceledException)
        {
            Console.WriteLine("Operation was canceled.");
        }
    }
}
```

**LINQ example:**

```csharp
public static async IAsyncEnumerable<int> GetNumbersAsync()
{
    for (int i = 1; i <= 10; i++)
    {
        await Task.Delay(500);
        yield return i;
    }
}

public static async Task Main()
{
    await foreach (var even in GetNumbersAsync().Where(x => x % 2 == 0))
        Console.WriteLine(even); // 2, 4, 6, 8, 10
}
```

## What is the record type in C#?

A **record** (C# 9.0+) is a reference type for immutable data models with concise syntax, **value-based equality**, and built-in `Equals`, `GetHashCode`, `ToString`, deconstruction, and `with` cloning.

**Key features:**

- Immutable by default (`init` accessors).
- Value equality — two records are equal when all property values match.
- Positional syntax — primary constructor parameters become properties.
- Supports inheritance between records.

**Basic declaration and equality:**

```csharp
public record Person(string FirstName, string LastName);

var person1 = new Person("John", "Doe");
var person2 = new Person("John", "Doe");
Console.WriteLine(person1 == person2); // True
```

**`init` properties (equivalent expanded form):**

```csharp
public record Person
{
    public string FirstName { get; init; }
    public string LastName { get; init; }
}
var person = new Person { FirstName = "John", LastName = "Doe" };
// person.FirstName = "Jane"; // Compile error
```

**Inheritance and `with`:**

```csharp
public record Person(string FirstName, string LastName);
public record Employee(string FirstName, string LastName, string Position)
    : Person(FirstName, LastName);

var person1 = new Person("John", "Doe");
var person2 = person1 with { LastName = "Smith" };
// Person { FirstName = John, LastName = Smith }

var (firstName, lastName) = person1;
Console.WriteLine($"{firstName} {lastName}"); // John Doe
```

| Feature | Records | Classes |
|---------|---------|---------|
| Equality | Value-based | Reference-based |
| Immutability | Default (`init`) | Mutable by default |
| Syntax | Positional, `with` | Standard |
| Deconstruction | Built-in | Manual |

**Use for:** DTOs, immutable value objects, deduplication/caching by value.

## Explain default interface methods?

**Default interface methods** (C# 8.0) let interfaces provide method bodies so new members can be added without breaking existing implementers.

**Key points:**

- Backward compatible — implementers inherit defaults unless they override.
- Shared logic in the interface; no instance fields or constructors.
- Conflict resolution required when multiple interfaces define the same default method.

**Declaring defaults:**

```csharp
public interface ILogger
{
    void Log(string message);
    void LogInfo(string message) => Console.WriteLine($"INFO: {message}");
    void LogError(string message) => Console.WriteLine($"ERROR: {message}");
}
```

**Implementing — only non-default members required:**

```csharp
public class ConsoleLogger : ILogger
{
    public void Log(string message) => Console.WriteLine($"Log: {message}");
    public void LogError(string message) => Console.WriteLine($"Console Error: {message}");
    // LogInfo uses interface default
}
```

**Usage:**

```csharp
ILogger logger = new ConsoleLogger();
logger.Log("Starting application...");       // Implemented
logger.LogInfo("Application is running.");   // Default
logger.LogError("An error occurred.");       // Overridden
```

**Explicit implementation:**

```csharp
public class FileLogger : ILogger
{
    void ILogger.LogInfo(string message) => Console.WriteLine($"File INFO: {message}");
    public void Log(string message) => Console.WriteLine($"File Log: {message}");
}
```

**Inherited defaults:**

```csharp
public interface IAdvancedLogger : ILogger
{
    void LogWarning(string message) => Console.WriteLine($"WARNING: {message}");
}
```

**Conflict resolution:**

```csharp
public interface IFirst  { void Print() => Console.WriteLine("First interface"); }
public interface ISecond { void Print() => Console.WriteLine("Second interface"); }

public class CombinedClass : IFirst, ISecond
{
    public void Print() => Console.WriteLine("Combined class implementation");
}
```

**Use when:** evolving APIs without breaking consumers, or sharing default behavior across implementers. Unlike abstract classes, interfaces still cannot hold state.

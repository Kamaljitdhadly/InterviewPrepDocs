## How do push notifications work?

**Push notifications** are server-to-device messages delivered even when the app isn't active — used for real-time alerts, updates, and engagement.

**Flow:**

1. **User opt-in** — permission prompt on mobile/web.
2. **Registration** — device registers with push service (**APNs** for iOS, **FCM** for Android/web); receives unique **device token** sent to backend.
3. **Backend** — stores token linked to user account.
4. **Send** — backend composes message + token → push service.
5. **Delivery** — APNs/FCM routes to device (even if app closed).
6. **Display** — banner, alert, badge, sound, or vibration per device settings.
7. **Interaction** — tap opens app and triggers relevant action.

**Key components:**

| Component | Role |
|-----------|------|
| **APNs** | iOS push delivery |
| **FCM** | Android + web push |
| **Backend server** | Notification logic and token management |

**Use cases:** messaging, news alerts, e-commerce order updates, social notifications.

**Security:** encrypt notification data; securely manage device tokens to prevent misdelivery.

Use judiciously to avoid user fatigue.

## How does VAPID authentication work with FCM?

**VAPID** (Voluntary Application Server Identification) lets FCM verify your server's identity when sending web push notifications.

**Workflow:**

1. **Generate VAPID keys** (public + private pair).
2. **Client subscribes** — browser sends subscription (including public key) to your server.
3. **Server signs** — private key signs the push request to FCM.
4. **FCM verifies** — validates JWT with public key; delivers to client if valid.

### Step 1: Generate VAPID Keys

```bash
npm install web-push -g
web-push generate-vapid-keys
```

```json
{
  "publicKey": "YourPublicKeyHere",
  "privateKey": "YourPrivateKeyHere"
}
```

### Step 2: Client Subscription (Angular)

Client subscribes via Service Worker API; subscription includes VAPID public key for message encryption.

```typescript
import { SwPush } from '@angular/service-worker';
import { HttpClient } from '@angular/common/http';
import { Injectable } from '@angular/core';

@Injectable({ providedIn: 'root' })
export class PushNotificationService {
  readonly VAPID_PUBLIC_KEY = 'YourPublicKeyHere';

  constructor(private swPush: SwPush, private http: HttpClient) {}

  subscribeToNotifications() {
    this.swPush.requestSubscription({
      serverPublicKey: this.VAPID_PUBLIC_KEY
    })
    .then(subscription => {
      this.http.post('/api/push/subscribe', subscription)
        .subscribe(() => console.log('Subscribed successfully'));
    })
    .catch(err => console.error('Subscription failed', err));
  }
}
```

### Step 3: Server Signs and Sends (ASP.NET Core)

Store keys in `appsettings.json`:

```json
{
  "VapidKeys": {
    "PublicKey": "YourPublicKeyHere",
    "PrivateKey": "YourPrivateKeyHere"
  }
}
```

```csharp
public class PushNotificationService
{
    private readonly PushServiceClient _pushClient;
    private readonly string _subject;
    private readonly string _publicKey;
    private readonly string _privateKey;

    public PushNotificationService(IConfiguration configuration)
    {
        _subject = "mailto:your-email@example.com";
        _publicKey = configuration["VapidKeys:PublicKey"];
        _privateKey = configuration["VapidKeys:PrivateKey"];
        _pushClient = new PushServiceClient();
        _pushClient.DefaultAuthentication = new VapidAuthentication(_subject, _publicKey, _privateKey);
    }

    public async Task SendNotificationAsync(PushSubscription subscription, string payload)
    {
        var pushMessage = new PushMessage(payload, null);
        await _pushClient.RequestPushMessageDeliveryAsync(subscription, pushMessage);
    }
}
```

### Step 4: FCM Authenticates and Delivers

- Server sends push request with **JWT** in `Authorization` header, signed by VAPID private key.
- JWT contains `iss` (issuer email), `sub` (subject), `exp` (expiration).
- FCM verifies JWT using the VAPID public key from client subscription.
- On success, notification delivered to client; service worker handles display.

**JWT format (conceptual):**

```
eyJhbGciOiJSUzI1NiIsImtpZCI6IjMwNDMiLCJ0eXAiOiJKV1QifQ...
```

Sent as:

```http
Authorization: WebPush <JWT>
```

**Summary:** generate VAPID keys → client subscribes with public key → server signs with private key → FCM verifies and delivers.

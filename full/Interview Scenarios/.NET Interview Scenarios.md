## How do you implement secure JWT logout and refresh rotation?

**Context:** Mobile app logout must stop a **stolen refresh token** from minting new access tokens indefinitely. Access tokens are short-lived; refresh tokens are the real session handle.

**What trips people up:** Deleting cookies client-side without server revocation or rotation.

**Production pattern:**

```text
Login   → access (15m) + refresh (7d, hashed in DB, family id)
Refresh → rotate refresh (invalidate old), issue new pair
Logout  → revoke entire refresh family
Reuse   → old refresh presented after rotation → revoke family (breach detection)
```

```csharp
public async Task<TokenPair> RefreshAsync(string refreshToken)
{
    var stored = await _store.FindByHash(Hash(refreshToken))
        ?? throw new SecurityException();

    if (stored.Revoked)
    {
        await _store.RevokeFamilyAsync(stored.FamilyId);
        throw new SecurityException();
    }

    await _store.RevokeAsync(stored.Id);
    return await IssueNewPairAsync(stored.UserId, stored.FamilyId);
}
```

**Strong close:** "Refresh rotation + reuse detection — stolen refresh token triggers family revoke."

## User A sees User B's data after deploy?

**Context:** Multi-tenant API. After deploy or scale-out, users report seeing another tenant's data intermittently.

**Common cause:** `TenantContext` registered **Singleton** but populated from JWT per request — first request "wins" and caches tenant ID for all users.

```csharp
// Bug — singleton captures tenant from first request
public class ReportService
{
    private readonly int _tenantId;
    public ReportService(TenantContext ctx) => _tenantId = ctx.TenantId;
}

// Fix — read tenant per operation
var tenantId = _httpContextAccessor.HttpContext!.User.GetTenantId();
```

**Also check:** Wrong `sub` / `tenant_id` claim mapping; missing `[Authorize]` on new endpoints.

**Strong close:** "Singleton must never capture scoped or request state — resolve tenant from `HttpContext` per call."

## AddDbContextPool vs AddDbContext — subtle bugs?

**Context:** Team enables `AddDbContextPool` for throughput. Random wrong calculations or stale flags appear under load.

**Cause:** Pool **reuses** `DbContext` instances. Custom **mutable instance fields** on the context survive across requests if not reset in `OnConfiguring` / overridden `Dispose`.

| Use pool when | Avoid pool when |
|---------------|-----------------|
| Standard EF, no mutable instance state | Custom mutable fields on `DbContext` |
| High-throughput read-heavy API | Heavy per-instance setup that isn't reset |

**Fix:** No mutable state on context; use scoped services for per-request state.

**Strong close:** "Pooling assumes context is resettable — treat it like a rented object."

## Middleware order — JWT auth after authorization?

**Context:**

```csharp
app.UseAuthorization();
app.UseAuthentication();  // WRONG
```

**Result:** `[Authorize]` runs before user is authenticated — 401 everywhere, or policies never see claims.

**Correct order:**

```csharp
app.UseAuthentication();
app.UseAuthorization();
```

**Variant:** In older templates, endpoints mapped before authentication middleware — same class of bug.

**Strong close:** "Authentication populates `HttpContext.User` before authorization reads it — order is contractual."

## Health Healthy but app cannot serve traffic?

**Context:** `/health` returns 200. All API calls timeout. On-call assumes "app is fine."

**Cause:** Health only checks process alive. **DB connection pool exhausted** or thread pool starved — liveness green, readiness should be red.

```csharp
builder.Services.AddHealthChecks()
    .AddSqlServer(connectionString, tags: new[] { "ready" })
    .AddRedis(redisConn, tags: new[] { "ready" });

app.MapHealthChecks("/health/ready", new() { Predicate = c => c.Tags.Contains("ready") });
app.MapHealthChecks("/health/live");  // minimal — process up only
```

**Kubernetes:** Remove pod from Service when **readiness** fails; don't restart on readiness (use **liveness** only for deadlocks).

**Strong close:** "Liveness = process up; readiness = can serve traffic including dependencies."

## IHostedService stops after unhandled exception?

**Context:** Background worker processes queue messages. One poison message throws; loop exits; queue backs up for days unnoticed.

```csharp
protected override async Task ExecuteAsync(CancellationToken stoppingToken)
{
    while (!stoppingToken.IsCancellationRequested)
    {
        try
        {
            await ProcessNextAsync(stoppingToken);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Worker failed — continuing");
            await Task.Delay(TimeSpan.FromSeconds(5), stoppingToken);
        }
    }
}
```

**Better:** Polly retries, dead-letter queue for poison messages, metrics on consecutive failures.

**Strong close:** "Background services must never die on one bad message — catch, DLQ, alert."

## Response compression + caching — garbled JSON?

**Context:** Browser or mobile client shows binary garbage instead of JSON after enabling compression behind CDN.

**Causes:** CDN caches compressed body without `Vary: Accept-Encoding`; or **double compression** (app + reverse proxy).

**Fix:** Set `Vary: Accept-Encoding`; don't compress already-compressed types; align CDN cache key with encoding.

**Strong close:** "Caching and compression interact — `Vary` and single compression point."

## Rate limiting by IP behind Azure Front Door?

**Context:** Rate limiter uses `RemoteIpAddress`. Behind Front Door, every request appears from **one IP** — one abusive client blocks everyone.

```csharp
// ForwardedHeadersMiddleware with known proxy networks
// Rate limit by authenticated user id or API key when possible
// Trust X-Forwarded-For only from Front Door IP ranges
```

**Strong close:** "Behind a proxy, rate limit on identity — not connection IP — unless forwarded headers are trusted."

## ProblemDetails leaks stack trace in prod?

**Context:** Global exception handler returns full exception details to API clients — security audit finding.

```csharp
options.IncludeExceptionDetails = (ctx, ex) => env.IsDevelopment();
```

**Prod response:** Generic title, `type` URI, **trace id** for support correlation — full stack in logs only.

**Strong close:** "Clients get trace id; operators get stack trace in structured logs."

## Minimal API — DbContext captured in closure?

**Context:** Endpoints registered in a loop; classic closure bug captures wrong route value, or scoped `DbContext` captured in static delegate and used after dispose.

**Fix:** Use injected parameters in route handlers (`MapGet("/{id}", async (int id, AppDbContext db) => ...)`); don't close over loop variables or scoped services incorrectly.

**Strong close:** "Minimal APIs still follow DI scopes — inject per request, don't capture in static closures."

## gRPC and REST on same Kestrel — load balancer issue?

**Context:** ALB terminates TLS and speaks HTTP/1.1 to backend. gRPC requires **HTTP/2** → `UNAVAILABLE` errors.

**Fix:** HTTP/2 end-to-end (ALB HTTP/2 to target), gRPC-Web for browser clients, or dedicated gRPC port with correct LB config.

**Strong close:** "gRPC is HTTP/2 — LB and TLS termination must preserve it."

## Zero-downtime deploy + DB migration?

**Context:** Single deploy step: new code + `DROP COLUMN` migration. Old pods still running → `SqlException` for users on old version.

**Expand-contract:**

```text
1. ADD nullable column (deploy migration)
2. Deploy code writing both old and new
3. Backfill
4. Deploy code reading new only
5. DROP old column
```

**Strong close:** "Schema and code version independently during rollout — expand-contract is non-negotiable at scale."

## What are nullable reference types in C#?

**nullable reference types** were introduced as a new feature aimed at improving code safety and reducing the risk of NullReferenceException by making it clear when null is allowed or not for reference types.

Before this feature, reference types in C# (like string, object, etc.) were implicitly nullable, meaning you could assign null to any reference type variable, potentially leading to NullReferenceException errors if not handled carefully. Nullable reference types address this issue by allowing developers to explicitly express whether a reference type can or cannot be null.

### Key Concepts of Nullable Reference Types

1.  **Nullable Reference Types (string?)**:

    - You explicitly declare that a reference type can be null using the ? annotation.

    - Example: string? name; means that the variable name can be assigned null.

2.  **Non-nullable Reference Types (string)**:

    - By default (in C# 8.0 and later with nullable reference types enabled), reference types are **non-nullable**, meaning they cannot be assigned null unless explicitly marked with ?.

    - Example: string name; means that name cannot be null, and the compiler will warn you if it’s not properly initialized.

3.  **Nullable Annotations**:

    - You use the ? symbol to indicate that a reference type is nullable. This is only available when nullable reference types are enabled.

    - Example: int? for nullable value types existed in earlier versions of C#, and now string? is available for nullable reference types.

4.  **Nullable Warnings**:

    - The compiler generates warnings if it detects that you are assigning null to a non-nullable reference type or if you’re using a nullable reference type without checking for null.

### Enabling Nullable Reference Types

Nullable reference types are **opt-in**. To enable this feature, you can:

- Add the following directive at the top of your file or project:

```csharp
#nullable enable
```

- You can also enable it in the .csproj file:

```csharp
<Nullable>enable</Nullable>
```

### Example of Nullable Reference Types

#nullable enable

```csharp
public class Person
{
public string Name { get; set; } // Non-nullable, cannot be null
public string? Address { get; set; } // Nullable, can be null
}
public class Program
{
public static void Main()
{
Person person = new Person();
```

person.Name = "John"; // Valid, Name is non-nullable

person.Address = null; // Valid, Address is nullable

```csharp
Console.WriteLine(person.Name.Length); // Safe: Name is non-nullable
if (person.Address != null)
{
Console.WriteLine(person.Address.Length); // Safe: Address is nullable but checked for null
}
}
}
```

### Benefits of Nullable Reference Types

1.  **Prevent NullReferenceException:**

    - Nullable reference types help reduce the risk of runtime NullReferenceException by warning you during compilation when you might unintentionally work with null.

2.  **Clearer Code Contracts:**

    - It becomes clearer in your code when a variable can or cannot be null, improving code readability and intent.

3.  **Enhanced Static Analysis:**

    - The compiler performs static analysis to ensure you're handling null properly, providing warnings when there are potential risks of null dereferencing.

### Nullable Reference Type Contexts

Nullable reference types introduce three contexts:

1.  **Enabled Context (#nullable enable)**: The compiler enforces nullable annotations (?) and warnings are generated if you break nullability rules.

2.  **Disabled Context (#nullable disable)**: The behavior is as it was before C# 8.0—reference types are nullable by default.

3.  **Warnings Context (#nullable warnings)**: The compiler warns about nullable reference types, but annotations are not enforced.

### Example: Nullable Contexts

#nullable enable

string? nullableString = null; // Allowed

```csharp
string nonNullableString = "Hello";
```

nonNullableString = null; // Compiler warning

#nullable disable

```csharp
string oldStyleNullableString = null; // No warning
```

### Summary

- **Nullable reference types** in C# 8.0+ allow you to explicitly specify whether reference types can or cannot be null.

- **Non-nullable reference types** are the default, helping to reduce NullReferenceException errors by requiring that you handle nullable types explicitly.

- You can enable this feature at the project level or file level, and the compiler will provide warnings to help you manage null safely.

## Describe pattern matching enhancements in recent C# versions?

C# has introduced several **pattern matching enhancements** in recent versions, starting from C# 7.0 and continuing through later versions (C# 8.0, 9.0, 10.0, and 11.0). These enhancements allow for more expressive and readable code, particularly when working with types, conditions, and control flow. Let’s break down the key enhancements:

### 1. **C# 7.0: Initial Introduction of Pattern Matching**

Pattern matching was first introduced in C# 7.0, mainly through the is keyword and switch expressions.

#### a. **Type Pattern (**is**)**:

- This pattern allows you to check the type of an object and cast it in a single operation.

Example:

object obj = "Hello, World!";

```csharp
if (obj is string s)
{
Console.WriteLine(s.Length); // Safe: obj is a string
}
```

#### b. **Switch Statement with Pattern Matching**:

- Switch statements were enhanced to support pattern matching based on types and values.

Example:

object obj = 42;

switch (obj)

```csharp
{
case int i:
Console.WriteLine($"Integer: {i}");
break;
case string s:
Console.WriteLine($"String: {s}");
break;
```

default:

```csharp
Console.WriteLine("Unknown type");
break;
}
```

### 2. **C# 8.0: Enhanced Pattern Matching**

C# 8.0 brought **more powerful pattern matching** capabilities, including switch expressions, property patterns, and positional patterns.

#### a. **Switch Expressions**:

- A more concise way of writing switch statements that return values directly.

Example:

```csharp
int number = 10;
string result = number switch
{
0 => "Zero",
1 => "One",
_ => "Other"
};
Console.WriteLine(result); // Output: Other
```

#### b. **Property Patterns**:

- Allows pattern matching on the properties of objects.

Example:

```csharp
public class Person
{
public string Name { get; set; }
public int Age { get; set; }
}
Person person = new Person { Name = "John", Age = 30 };
if (person is { Name: "John", Age: > 20 })
{
Console.WriteLine("John is over 20 years old.");
}
```

#### c. **Positional Patterns**:

- Used with types like tuples and deconstructable types.

Example:

```csharp
public class Point
{
public int X { get; }
public int Y { get; }
public void Deconstruct(out int x, out int y) => (x, y) = (X, Y);
}
Point point = new Point(3, 4);
var message = point switch
{
(0, 0) => "Origin",
(var x, var y) when x == y => "Diagonal",
_ => "Some other point"
};
Console.WriteLine(message); // Output: Some other point
```

### 3. **C# 9.0: New Patterns**

C# 9.0 introduced several new patterns to make pattern matching even more expressive.

#### a. **Relational Patterns**:

- Allow you to match values based on relational operators like <, >, <=, and >=.

Example:

```csharp
int age = 25;
var category = age switch
{
< 13 => "Child",
>= 13 and < 20 => "Teenager",
>= 20 and < 65 => "Adult",
_ => "Senior"
};
Console.WriteLine(category); // Output: Adult
```

#### b. **Logical Patterns (**and**,** or**,** not**)**:

- These patterns allow combining multiple patterns with logical operators (and, or, not).

Example:

```csharp
int number = 15;
var category = number switch
{
> 0 and <= 10 => "Between 1 and 10",
> 10 and <= 20 => "Between 11 and 20",
_ => "Other"
};
Console.WriteLine(category); // Output: Between 11 and 20
```

Example with not:

object obj = "hello";

if (obj is not null)

```csharp
{
Console.WriteLine("Object is not null");
}
```

### 4. **C# 10.0: Constant and Parenthesized Patterns**

C# 10.0 continued to refine pattern matching by adding constant and parenthesized patterns.

#### a. **Constant Patterns**:

- Constants are allowed directly in patterns.

Example:

```csharp
int number = 10;
string message = number switch
{
10 => "Ten",
20 => "Twenty",
_ => "Other"
};
Console.WriteLine(message); // Output: Ten
```

#### b. **Parenthesized Patterns**:

- Group patterns together using parentheses.

Example:

```csharp
int number = 5;
var result = number switch
{
(>= 1 and <= 10) => "Between 1 and 10",
_ => "Other"
};
Console.WriteLine(result); // Output: Between 1 and 10
```

### 5. **C# 11.0: More Pattern Matching Enhancements**

C# 11.0 introduced **list patterns** and **required members**, adding flexibility to work with more complex data structures.

#### a. **List Patterns**:

- List patterns allow pattern matching on arrays and lists.

Example:

int[] numbers = { 1, 2, 3 };

```csharp
var result = numbers switch
{
[1, 2, 3] => "Exact match",
[1, 2, ..] => "Starts with 1 and 2",
_ => "No match"
};
Console.WriteLine(result); // Output: Exact match
```

#### b. **Required Members**:

- While not specifically a pattern-matching feature, C# 11 introduced **required properties**, which enforce certain members to be initialized.

Example:

```csharp
public class Person
{
public required string Name { get; init; }
public required int Age { get; init; }
}
```

### Summary of Pattern Matching Enhancements by Version:

- **C# 7.0**: Type patterns (is), switch patterns.

- **C# 8.0**: Switch expressions, property patterns, positional patterns.

- **C# 9.0**: Relational patterns, logical patterns (and, or, not).

- **C# 10.0**: Constant patterns, parenthesized patterns.

- **C# 11.0**: List patterns, required members.

## What are asynchronous streams (IAsyncEnumerable)?

**Asynchronous streams**, represented by the IAsyncEnumerable<T> interface in C# 8.0 and later, allow you to asynchronously iterate over collections of data that are fetched or generated in a non-blocking, asynchronous manner. This feature is particularly useful when working with large data sets, streams of events, or I/O-bound data sources like databases or web APIs where data is processed incrementally as it becomes available.

### Key Concepts of Asynchronous Streams (IAsyncEnumerable<T>)

1.  **Asynchronous Enumeration**:

    - IAsyncEnumerable<T> enables the iteration over a collection where the items are fetched or processed asynchronously, unlike `IEnumerable<`T>, which is synchronous.

    - Instead of using foreach or MoveNext synchronously, you use await foreach to asynchronously wait for the next item to be fetched or processed.

2.  **Asynchronous Yielding**:

    - You can use yield return in combination with await inside an asynchronous method to yield items one by one as they are produced.

3.  **Efficient Resource Use**:

    - Asynchronous streams are ideal when working with data that may not be available all at once (e.g., streaming data from a network or a database), making it more efficient by not blocking threads while waiting for data.

4.  **Lazy Data Fetching**:

    - Data is fetched only as needed, so you don’t have to wait for the entire data set to be ready before starting the processing.

### Syntax and Usage

#### 1. **Declaring and Consuming an Asynchronous Stream**

To declare a method that returns an asynchronous stream, use IAsyncEnumerable<T> as the return type and async modifier on the method. You then consume the stream using await foreach.

##### Example:

```csharp
public class AsyncStreamExample
{
// Method returning an async stream
public async IAsyncEnumerable<int> GetNumbersAsync()
{
for (int i = 1; i <= 5; i++)
{
```

await Task.Delay(1000); // Simulate asynchronous work

```csharp
yield return i; // Yield each number asynchronously
}
}
}
public class Program
{
public static async Task Main()
{
var example = new AsyncStreamExample();
// Asynchronously iterate over the stream
await foreach (int number in example.GetNumbersAsync())
{
Console.WriteLine(number); // Output: 1, 2, 3, 4, 5 (with 1 second delay between each)
}
}
}
```

- The GetNumbersAsync method generates numbers 1 through 5, with a 1-second delay between each one, simulating an asynchronous operation.

- In the Main method, await foreach is used to consume the numbers as they are asynchronously yielded by the GetNumbersAsync method.

#### 2. **Working with Cancellation**

You can also support cancellation in asynchronous streams by accepting a CancellationToken parameter in the method and passing it to the await foreach loop.

##### Example with Cancellation:

```csharp
public class AsyncStreamWithCancellation
{
public async IAsyncEnumerable<int> GetNumbersAsync(CancellationToken cancellationToken)
{
for (int i = 1; i <= 5; i++)
{
```

await Task.Delay(1000, cancellationToken); // Cancelable delay

```csharp
yield return i; // Yield each number asynchronously
if (cancellationToken.IsCancellationRequested)
```

yield break; // Stop iteration if cancellation is requested

```csharp
}
}
}
public class Program
{
public static async Task Main()
{
var example = new AsyncStreamWithCancellation();

```

```csharp

- The CancellationToken allows for graceful cancellation of the asynchronous enumeration, stopping the loop if the operation is canceled.

#### 3. **Using LINQ with Asynchronous Streams**

You can use LINQ-like operations with IAsyncEnumerable<T>, such as Where, Select, and other query operators in an asynchronous manner. These methods are available in System.Linq.Async.

##### Example with LINQ:

```

### Advantages of Asynchronous Streams

1.  **Non-blocking operations**: Asynchronous streams don’t block the calling thread while waiting for data, making them ideal for I/O-bound operations (e.g., reading files, querying databases).

2.  **Efficient handling of large data sets**: Asynchronous streams allow you to process data incrementally as it becomes available, which is more efficient than loading large data sets all at once into memory.

3.  **Better resource management**: Asynchronous streams often work better in cases where you have to wait for data (like fetching data from a remote server) or work with infinite sequences (e.g., event streams or real-time data).

4.  **Cancellation support**: With built-in support for CancellationToken, you can cancel the stream mid-execution, giving you control over long-running operations.

### Common Use Cases

- **Processing paginated data from an API**: Instead of loading all the data at once, fetch and process each page of data asynchronously as it’s received.

- **Streaming file reading**: Process large files line by line without blocking the calling thread.

- **Database queries**: Fetch data asynchronously as the database returns results rather than waiting for the entire query to complete.

- **Real-time data processing**: Listen for events, messages, or sensor data streams and handle them asynchronously as they come in.

### Summary

- IAsyncEnumerable<T> is an interface that represents an asynchronous sequence of elements, allowing for non-blocking iteration using await foreach.

- It is useful when working with large, paginated, or streaming data sets where the data may not be available all at once.

- Asynchronous streams make your code more responsive and efficient by preventing thread blocking during I/O operations.

## What is the record type in C#?

In C#, a **record type** is a reference type introduced in C# 9.0 that provides a concise syntax for creating immutable data models or "data objects" with built-in features for value-based equality, immutability, and structural comparisons. Records are primarily used to represent data with less boilerplate code compared to classes, making them an ideal choice for scenarios where the focus is on data rather than behavior.

### Key Features of Records

1.  **Immutable by Default**:

    - Records are immutable by default, meaning their properties are read-only after initialization, though this can be adjusted if needed.

    - You can define records with init accessors, allowing the properties to be set only during object initialization.

2.  **Value-based Equality**:

    - Unlike classes (which compare references), records implement **value-based equality** by default. Two records are considered equal if their properties have the same values, regardless of whether they refer to the same object in memory.

3.  **Concise Syntax**:

    - Records reduce boilerplate code by providing a concise syntax to define properties and automatically generate constructors, equality methods, GetHashCode(), and ToString().

4.  **Deconstruction Support**:

    - Records automatically support deconstruction, allowing you to break them down into their individual properties in a straightforward manner.

5.  **Inheritance**:

    - Records support inheritance, just like classes. You can derive one record from another.

### Syntax and Usage

#### 1. **Basic Record Declaration**

A simple example of defining a record:

```csharp
public record Person(string FirstName, string LastName);
```

This defines a record Person with two properties: FirstName and LastName. It automatically generates:

- A constructor with parameters for FirstName and LastName.

- Equals() and GetHashCode() methods based on the values of the properties.

- A ToString() method that provides a readable representation of the record (e.g., Person { FirstName = "John", LastName = "Doe" }).

#### 2. **Instantiating a Record**

```csharp
var person1 = new Person("John", "Doe");
var person2 = new Person("John", "Doe");
Console.WriteLine(person1 == person2); // True (Value-based equality)
```

Even though person1 and person2 are different objects in memory, they are considered equal because their properties have the same values (FirstName = "John" and LastName = "Doe").

#### 3. **Immutable Properties with** init

Records allow you to define properties with the init accessor, making them immutable after object initialization:

public record Person

```csharp
{
public string FirstName { get; init; }
public string LastName { get; init; }
}
var person = new Person { FirstName = "John", LastName = "Doe" };
// person.FirstName = "Jane"; // This would cause a compilation error
```

Once the record is initialized, its properties cannot be changed.

#### 4. **Positional Records**

You can use positional records, which provide a more concise syntax to define records with constructor parameters:

```csharp
public record Person(string FirstName, string LastName);
```

This is equivalent to writing:

public record Person

```csharp
{
public string FirstName { get; init; }
public string LastName { get; init; }
public Person(string firstName, string lastName)
{
FirstName = firstName;
LastName = lastName;
}
}
```

#### 5. **Inheritance with Records**

Records can inherit from other records, just like classes:

```csharp
public record Person(string FirstName, string LastName);
public record Employee(string FirstName, string LastName, string Position) : Person(FirstName, LastName);
```

#### 6. **Cloning Records with** with **Expression**

You can create a copy of an existing record with modified values using the with expression, which is ideal for maintaining immutability:

```csharp
var person1 = new Person("John", "Doe");
var person2 = person1 with { LastName = "Smith" };
Console.WriteLine(person2); // Output: Person { FirstName = John, LastName = Smith }
```

This copies person1 into person2, only changing the LastName property.

#### 7. **Deconstruction**

Records support deconstruction, allowing you to extract their values into individual variables:

```csharp
var person = new Person("John", "Doe");
var (firstName, lastName) = person;
Console.WriteLine($"{firstName} {lastName}"); // Output: John Doe
```

### Key Differences Between Records and Classes

| **Feature** | **Records** | **Classes** |
|----|----|----|
| **Equality** | Value-based equality (compares property values) | Reference-based equality (compares memory references) |
| **Immutability** | Properties are immutable by default (using init) | Properties are mutable by default |
| **Concise Syntax** | Supports positional records and with expressions | No positional records or with expressions |
| **Deconstruction Support** | Automatic deconstruction syntax for extracting values | Deconstruction needs to be implemented manually |

### When to Use Records

- **Data transfer objects (DTOs)**: When creating models that primarily hold data and you don’t need to modify them after creation.

- **Immutable objects**: When immutability is desired, such as in functional programming paradigms.

- **Value-based equality**: When you want to compare objects based on their property values rather than their references (e.g., for caching, deduplication, or comparison logic).

### Summary

- **Records** in C# are reference types designed to represent data, with built-in value-based equality, immutability, and concise syntax.

- They simplify code, especially for immutable data models, data transfer objects, and scenarios requiring equality comparison based on property values.

- Key features include positional syntax, the with expression for cloning, and deconstruction.

## Explain default interface methods?

**Default interface methods** (also known as **default implementations**) were introduced in C# 8.0. This feature allows interfaces to provide a default implementation for some of their methods. This means that new methods can be added to an interface without breaking existing implementations of that interface in derived classes.

Before C# 8.0, if a new method was added to an interface, all classes implementing that interface would have to be modified to include an implementation for the new method. With default interface methods, this problem is resolved by providing a default implementation directly in the interface.

### Key Features of Default Interface Methods

1.  **Backward Compatibility**:

    - Default interface methods enable you to extend interfaces by adding new methods without breaking existing implementations of those interfaces.

    - Classes that implement the interface are not required to implement the new methods unless they want to override the default behavior.

2.  **Flexibility**:

    - Interfaces can now contain both method signatures and default implementations, similar to how abstract classes work, but still cannot contain instance fields or constructors.

3.  **Code Reusability**:

    - Shared functionality can be implemented directly in the interface and reused by multiple classes without the need to duplicate the logic in every class.

### Syntax and Usage

#### 1. **Declaring Default Interface Methods**

You declare a default interface method by providing a method body directly within the interface definition.

##### Example:

```csharp
public interface ILogger
{
// A method without a default implementation
void Log(string message);
// A method with a default implementation
void LogInfo(string message)
{
Console.WriteLine($"INFO: {message}");
}
// Another default method
void LogError(string message)
{
Console.WriteLine($"ERROR: {message}");
}
}
```

Here, LogInfo and LogError are default interface methods that provide default implementations. Classes that implement the ILogger interface are not required to override these methods unless they want to change the behavior.

#### 2. **Implementing an Interface with Default Methods**

When a class implements an interface with default methods, it only needs to provide implementations for methods without a default.

##### Example:

```csharp
public class ConsoleLogger : ILogger
{
// Implement the method without default implementation
public void Log(string message)
{
Console.WriteLine($"Log: {message}");
}
// Optionally, the class can override default methods
public void LogError(string message)
{
Console.WriteLine($"Console Error: {message}");
}
}
```

In the ConsoleLogger class:

- The Log method must be implemented because it doesn’t have a default implementation.

- The LogError method has been overridden to provide a custom implementation, while the LogInfo method is inherited from the interface with the default implementation.

#### 3. **Using Default Interface Methods**

You can call both the methods implemented by the class and the default methods from the interface.

##### Example:

```csharp
public class Program
{
public static void Main()
{
ILogger logger = new ConsoleLogger();
// Call the implemented method
logger.Log("Starting application...");
// Call the default method from the interface
logger.LogInfo("Application is running.");
// Call the overridden method
logger.LogError("An error occurred.");
}
}
```

**Output**:

Log: Starting application...

INFO: Application is running.

Console Error: An error occurred.

- logger.Log("...") calls the Log method implemented in the ConsoleLogger class.

- logger.LogInfo("...") calls the default LogInfo method from the ILogger interface because ConsoleLogger didn’t override it.

- logger.LogError("...") calls the overridden LogError method from the ConsoleLogger class.

#### 4. **Explicit Interface Implementation with Default Methods**

If a class needs to implement an interface method explicitly (i.e., accessible only via the interface reference), the default method can still be overridden.

##### Example:

```csharp
public class FileLogger : ILogger
{
// Explicit interface implementation
void ILogger.LogInfo(string message)
{
Console.WriteLine($"File INFO: {message}");
}
public void Log(string message)
{
Console.WriteLine($"File Log: {message}");
}
}
```

In this example, LogInfo is explicitly implemented and can only be called through an ILogger reference:

```csharp
ILogger logger = new FileLogger();
```

logger.LogInfo("File logging information"); // Calls the explicitly implemented method

#### 5. **Inheritance of Default Interface Methods**

If an interface inherits another interface with default methods, those methods are inherited as well, and a class implementing the derived interface can inherit or override the default methods.

##### Example:

```csharp
public interface IAdvancedLogger : ILogger
{
void LogWarning(string message)
{
Console.WriteLine($"WARNING: {message}");
}
}
public class AdvancedConsoleLogger : IAdvancedLogger
{
public void Log(string message)
{
Console.WriteLine($"Advanced Log: {message}");
}
}
```

Here, AdvancedConsoleLogger implements IAdvancedLogger and inherits default methods from both ILogger and IAdvancedLogger.

### Key Points to Remember

1.  **Interfaces Still Don’t Have State**:

    - Default interface methods cannot have instance fields or instance constructors. They only contain method logic.

2.  **Multiple Interface Inheritance**:

    - If a class implements multiple interfaces with conflicting default implementations, the class must resolve the conflict by explicitly providing its own implementation.

##### Example of Conflict Resolution:

```csharp
public interface IFirst
{
void Print() => Console.WriteLine("First interface");
}
public interface ISecond
{
void Print() => Console.WriteLine("Second interface");
}
public class CombinedClass : IFirst, ISecond
{
// Resolving the conflict by explicitly implementing the method
public void Print()
{
Console.WriteLine("Combined class implementation");
}
}
```

3.  **When to Use Default Interface Methods**:

    - **Backward Compatibility**: If you need to extend an existing interface but want to avoid breaking existing implementations.

    - **Shared Default Behavior**: When you have shared logic across different implementations that can be defined in the interface, reducing redundancy.

### Summary

- **Default interface methods** allow interfaces to contain default implementations for methods, enabling backward compatibility and reducing the need for boilerplate code.

- They are useful for evolving APIs without breaking existing implementations and can provide shared default behavior across multiple classes.

- Although similar to abstract classes in providing method implementations, interfaces with default methods still cannot have state or instance constructors.

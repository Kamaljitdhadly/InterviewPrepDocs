# .NET Core Push Notifications

Push notifications are messages sent from a server to a user's device, typically a smartphone, tablet, or computer. They are used to deliver real-time updates, alerts, or messages, even when the user is not actively using the app or website that generates the notification.

Here's how push notifications generally work:

### 1. User Opt-In

- The user must first grant permission to receive push notifications. On mobile devices, this typically involves an opt-in prompt asking for permission to send notifications.

### 2. Registration and Token Generation

- When a user opts in, the device registers with a push notification service (such as Apple's APNs for iOS or Google's FCM for Android).

- The device receives a unique device token (or registration ID) from the service, which is then sent to the app's backend server.

### 3. Backend Server

- The app's backend server stores the device token and associates it with the user's account. This token will be used to send push notifications to that specific device.

### 4. Sending a Notification

- When the app wants to send a notification, the backend server composes a message and sends it, along with the device token, to the push notification service (APNs or FCM).

### 5. Push Notification Service

- The push notification service (APNs or FCM) receives the message and delivers it to the user's device using the stored device token.

- The service handles the routing and ensures that the notification reaches the correct device, even if the app is not currently running.

### 6. Device Receives Notification

- The user's device receives the push notification from the service. Depending on the device's settings, the notification may be displayed as a banner, alert, or icon badge, or it might trigger a sound or vibration.

### 7. User Interaction

- If the user interacts with the notification (e.g., by tapping it), the app is opened, and the relevant action is taken within the app.

### Key Components

- **APNs (Apple Push Notification Service):** Used for iOS devices to handle push notifications.

- **FCM (Firebase Cloud Messaging):** Used for Android devices (and also supports web push notifications).

- **Backend Server:** Where the logic for creating and sending notifications resides.

### Common Use Cases

- **Messaging Apps:** To notify users of new messages.

- **News Apps:** To deliver breaking news alerts.

- **E-commerce Apps:** To inform users about sales or order updates.

- **Social Media Apps:** To notify users of likes, comments, or friend requests.

### Security Considerations

- **Encryption:** Push notification data is often encrypted to protect user privacy.

- **Authentication:** Device tokens are securely managed to ensure notifications are sent only to the intended recipient.

Push notifications are a powerful tool for engaging users, but they should be used judiciously to avoid overwhelming or annoying users.

The process of authenticating push notifications using VAPID (Voluntary Application Server Identification) keys with Firebase Cloud Messaging (FCM) involves several steps. These steps ensure that the FCM servers can verify the authenticity of the sender (your server) and deliver the notifications to the appropriate client (web browser).

### Workflow Overview

1.  **Generate VAPID Keys:** Create a pair of VAPID keys (public and private) that will be used for signing the push notification requests.

2.  **Client Subscription:** The client (browser) subscribes to push notifications and sends the subscription details (including the VAPID public key) to your server.

3.  **Server Signs and Sends Push Notification:** Your server uses the VAPID private key to sign the push notification request and sends it to the FCM servers.

4.  **FCM Server Authenticates and Delivers:** The FCM server verifies the request using the VAPID public key and delivers the push notification to the client if the authentication is successful.

#### Step 2: Client Subscription

The client (typically an Angular app) subscribes to push notifications using the Service Worker API. The subscription includes the VAPID public key, which the client needs to encrypt the push message.

Example in Angular:

typescript

Copy code

import { SwPush } from '@angular/service-worker';

import { HttpClient } from '@angular/common/http';

import { Injectable } from '@angular/core';

@Injectable({ providedIn: 'root' })

```csharp
export class PushNotificationService {
readonly VAPID_PUBLIC_KEY = 'YourPublicKeyHere';
constructor(private swPush: SwPush, private http: HttpClient) {}
subscribeToNotifications() {
this.swPush.requestSubscription({
serverPublicKey: this.VAPID_PUBLIC_KEY
})
.then(subscription => {
// Send subscription to the server
this.http.post('/api/push/subscribe', subscription)
.subscribe(() => console.log('Subscribed successfully'));
})
.catch(err => console.error('Subscription failed', err));
}
}
```

#### Step 3: Server Signs and Sends Push Notification

When your server receives the subscription information from the client, it stores this information for later use. When a notification needs to be sent, the server signs the push notification request with the VAPID private key and sends it to the FCM servers.

Example in ASP.NET Core:

1.  **Store VAPID Keys in appsettings.json:**

```csharp
{
"VapidKeys": {
"PublicKey": "YourPublicKeyHere",
"PrivateKey": "YourPrivateKeyHere"
}
}
```

2.  **Send Notification to FCM:**

```csharp
public class PushNotificationService
{
private readonly PushServiceClient _pushClient;
private readonly string _subject;
private readonly string _publicKey;
private readonly string _privateKey;
public PushNotificationService(IConfiguration configuration)
{
_subject = "mailto:your-email@example.com";
_publicKey = configuration["VapidKeys:PublicKey"];
_privateKey = configuration["VapidKeys:PrivateKey"];
_pushClient = new PushServiceClient();
_pushClient.DefaultAuthentication = new VapidAuthentication(_subject, _publicKey, _privateKey);
}
public async Task SendNotificationAsync(PushSubscription subscription, string payload)
{
var pushMessage = new PushMessage(payload, null);
await _pushClient.RequestPushMessageDeliveryAsync(subscription, pushMessage);
}
}
```

#### Step 4: FCM Server Authenticates and Delivers

- **FCM Authentication:** When your server sends the push notification request to FCM, it includes a JWT (JSON Web Token) in the Authorization header. This token is signed using the VAPID private key and contains the public key and other information like the subject and expiration.

- **Verification by FCM:** FCM servers verify the JWT by using the VAPID public key that was shared with the client during the subscription process. If the verification is successful, FCM accepts the notification and proceeds to deliver it to the targeted device (client).

- **Notification Delivery:** The notification is then delivered to the client device, where it is handled by the service worker and displayed to the user.

### Summary

- **VAPID Keys:** Generated and used to authenticate push notifications.

- **Client Subscription:** The client subscribes using the VAPID public key.

- **Server-Side Signing:** Your server signs the push notification with the VAPID private key.

- **FCM Authentication:** FCM verifies the request using the VAPID public key and delivers the notification to the client if valid.

## How do you implement secure JWT logout and refresh rotation in ASP.NET Core?

**Scenario:** Mobile app logout must prevent stolen refresh token from getting new access tokens.

**Production pattern:**

```text
Login  → access (15m) + refresh (7d, stored hashed in DB, family id)
Refresh → rotate refresh (invalidate old), new access
Logout → delete refresh family / mark revoked
Reuse detected → revoke entire token family (stolen refresh attack)
```

```csharp
public async Task<TokenPair> RefreshAsync(string refreshToken)
{
    var stored = await _store.FindByHash(Hash(refreshToken))
        ?? throw new SecurityException();

    if (stored.Revoked)
    {
        await _store.RevokeFamilyAsync(stored.FamilyId);  // breach response
        throw new SecurityException();
    }

    await _store.RevokeAsync(stored.Id);
    return await IssueNewPairAsync(stored.UserId, stored.FamilyId);
}
```

**90% miss:** Refresh token **rotation** + **reuse detection** — not just delete cookie on client.

## User A sees User B's data after deploy — scoped service bug or wrong claim?

**Scenario:** `TenantContext` registered Scoped but populated in middleware from JWT. Developer registers `TenantContext` as **Singleton** by mistake.

**Or:** `IHttpContextAccessor` used inside Singleton without reading per-request.

```csharp
// Bug — singleton caches tenant from first request
public class ReportService  // singleton
{
    private readonly int _tenantId;
    public ReportService(TenantContext ctx) => _tenantId = ctx.TenantId;
}

// Fix — resolve tenant per operation
public async Task RunAsync()
{
    var tenantId = _httpContextAccessor.HttpContext!.User.GetTenantId();
}
```

**Diagnosis:** First user after cold start "owns" tenant; chaos after scale-out.

## AddDbContextPool vs AddDbContext — when does pooling cause subtle bugs?

**Scenario:** `DbContext` has instance field `_calculator` mutated in `SaveChanges`. Pooling **resets** state incompletely if you add custom fields.

**Symptoms:** Random wrong calculations, stale event flags, cross-tenant bleed in custom state.

| Use pool when | Avoid pool when |
|---------------|-----------------|
| Standard EF, no mutable instance state | Custom mutable fields on DbContext |
| High throughput API | Heavy `OnConfiguring` per instance |

**Fix:** Don't store mutable state on context; use scoped services. Or use non-pooled `AddDbContext`.

## Middleware order is wrong — JWT auth runs after authorization. What fails silently?

**Scenario:**

```csharp
app.UseAuthorization();
app.UseAuthentication();  // WRONG ORDER
```

**Result:** `[Authorize]` always sees unauthenticated user → 401 on everything, or worse, custom policies never see claims.

**Correct:**

```csharp
app.UseAuthentication();
app.UseAuthorization();
```

**Tricky variant:** `UseEndpoints` before `UseAuthentication` in old templates — same class of bug.

## Health check returns Healthy but app cannot serve traffic — realistic scenario?

**Scenario:** `/health` only checks process up. DB connection pool exhausted — health green, all API calls timeout.

```csharp
builder.Services.AddHealthChecks()
    .AddSqlServer(connectionString, tags: new[] { "ready" })
    .AddRedis(redisConn, tags: new[] { "ready" });

app.MapHealthChecks("/health/ready", new() { Predicate = c => c.Tags.Contains("ready") });
app.MapHealthChecks("/health/live", new() { Predicate = _ => false });  // or empty — just alive
```

**Kubernetes:** Liveness vs readiness — readiness must fail when dependencies fail.

## IHostedService stops processing after unhandled exception — why?

**Scenario:** Background worker throws once; loop exits; queue backs up for days.

```csharp
protected override async Task ExecuteAsync(CancellationToken stoppingToken)
{
    while (!stoppingToken.IsCancellationRequested)
    {
        try
        {
            await ProcessNextAsync(stoppingToken);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Worker failed — continuing");
            await Task.Delay(TimeSpan.FromSeconds(5), stoppingToken);
        }
    }
}
```

**Better:** `BackgroundService` + Polly + dead-letter for poison messages.

## Response compression + HTTPS + caching — browser shows garbled JSON. Cause?

**Scenario:** CDN caches compressed response without `Vary: Accept-Encoding`, or double compression (app + nginx).

**Fix:** Ensure `Vary: Accept-Encoding`, disable compression on already compressed formats, align CDN cache keys.

## Rate limiting by IP behind Azure Front Door — everyone shares one bucket. Fix?

**Scenario:** `X-Forwarded-For` not trusted; rate limiter sees load balancer IP only → one customer DDoS blocks all users.

## ProblemDetails leaks stack trace in prod — how should errors flow?

**Scenario:** Exception middleware dumps full exception to client — security audit failure.

```csharp
// Dev: details. DeveloperExceptionPage
// Prod: ProblemDetails with generic title, trace id in logs only
options.IncludeExceptionDetails = (ctx, ex) => env.IsDevelopment();
```

Log correlation id (`Activity.Current?.Id`) in response extension for support — not stack trace.

## Minimal API endpoint captures DbContext in closure from outer scope — bug?

**Scenario:** Building endpoints in loop without proper closure capture — all endpoints hit same route parameter value (classic C# loop closure) or share disposed context.

Use route handlers with injected parameters — don't capture scoped services in static delegates incorrectly.

## gRPC and REST on same Kestrel — HTTP/2 prior knowledge issue on load balancer?

**Scenario:** ALB terminates TLS with HTTP/1.1 to backend; gRPC requires HTTP/2 → `UNAVAILABLE`.

**Fix:** HTTP/2 end-to-end, or use gRPC-Web, or separate port for gRPC with proper LB config.

## Zero-downtime deploy: old and new API versions share DB schema migration — what breaks?

**Scenario:** Migration drops column while old pods still run → `SqlException` on old code.

**Expand-contract pattern:**
1. Deploy migration **add** new column (nullable)
2. Deploy new code writing both
3. Backfill
4. Deploy new code read new only
5. Drop old column

**Never** breaking schema + code in single atomic deploy at scale.

## What is a Docker volume, and why is it used?

A **Docker volume** is persistent storage managed by Docker, stored outside the container filesystem. Data survives container restarts and removals.

**Why use volumes:**

| Benefit | Description |
|---------|-------------|
| Data persistence | Data outlives container lifecycle |
| Data sharing | Multiple containers mount the same volume |
| Backup/restore | Easy archive and migration |
| Container independence | Replace containers without losing data |
| Performance | Optimized I/O vs bind mounts |
| Management | `docker volume` commands for CRUD |

**Usage:**


Mount with `-v` (short):

```bash
docker run -v my-volume:/data my-image
```

Mount with `--mount` (long, preferred for complex configs):

```bash
docker run --mount source=my-volume,target=/data my-image
```

Inspect and list:


## How do volumes differ from bind mounts?

| Aspect | Volumes | Bind Mounts |
|--------|---------|-------------|
| Management | Docker-managed (`/var/lib/docker/volumes/`) | Host path mapped directly |
| Isolation | Abstracted from host filesystem | Tied to specific host path |
| Persistence | Independent of container lifecycle | Depends on host path existing |
| Performance | Optimized for containers | Depends on host filesystem |
| Best for | DBs, app data, logs, shared data | Dev source code, config files |
| Create | `docker volume create my-volume` | No creation step |
| Mount syntax | `-v my-volume:/data` | `-v /host/path:/container/path` |

```bash
docker run -v my-volume:/data my-image
```

```bash
docker run -v /host/path:/container/path my-image
```

**Compose — volume:**

```bash
version: '3'
services:
app:
image: my-image
volumes:
- my-volume:/data
volumes:
my-volume:
```

**Compose — bind mount:**

```bash
version: '3'
services:
app:
image: my-image
volumes:
- /host/path:/container/path
```

**Rule of thumb:** volumes for production persistence; bind mounts for dev workflows needing direct host file access.

## How can you persist data generated by a Docker container?

**Methods:**

1. **Docker volumes** (preferred) — managed, isolated, performant.
2. **Bind mounts** — map host directories; good for development.
3. **Compose volumes** — declare named volumes in `docker-compose.yml`.
4. **Data containers** — legacy pattern; volumes are preferred today.
5. **External storage** — NFS, EBS, cloud storage for scale:

```bash
docker run -v nfs-server:/data my-image
```

6. **Backup and restore** — protect data regardless of method.

**Backup example:**

```bash
docker run --rm -v my-volume:/data -v $(pwd):/backup alpine tar czf /backup/backup.tar.gz /data
```

**Restore example:**

```bash
docker run --rm -v my-volume:/data -v $(pwd):/backup alpine tar xzf /backup/backup.tar.gz -C /data
```

## How do you share a volume between multiple Docker containers?

**Step 1 — create volume:**

```bash
docker volume create shared-volume
```

**Step 2 — mount in multiple containers:**

```bash
docker run -d -v shared-volume:/data --name container1 my-image
docker run -d -v shared-volume:/data --name container2 my-image
```

```bash
docker run -d --mount source=shared-volume,target=/data --name container1 my-image
docker run -d --mount source=shared-volume,target=/data --name container2 my-image
```

Changes by one container are visible to all others on the same volume.

**Access:** default read/write; all containers see changes immediately. For concurrent writes, implement locking or data management strategies.

**Example — shared logs:**

```bash
docker volume create logs-volume
docker run -d -v logs-volume:/var/log/webapp --name webapp my-webapp-image
docker run -d -v logs-volume:/var/log/logging --name logservice my-logservice-image
```

## Explain how to back up and restore a Docker volume.

Use a **temporary Alpine container** with `tar` to archive volume contents.

**Backup:**

```bash
docker run --rm -v volume_name:/data -v $(pwd):/backup alpine tar czf /backup/backup.tar.gz -C /data .
```

- `--rm` — remove container after completion.
- `-v volume_name:/data` — mount the volume.
- `-v $(pwd):/backup` — host directory for the archive.
- `tar czf` — compressed tarball of `/data` contents.

Verify: `ls -lh backup.tar.gz`

**Restore:**

```bash
docker volume create volume_name
```

```bash
docker run --rm -v volume_name:/data -v $(pwd):/backup alpine tar xzf /backup/backup.tar.gz -C /data
```

Verify:

```bash
docker run --rm -v volume_name:/data alpine ls -lh /data
```

**Automated backup script (backup.sh):**

```bash
docker run --rm -v volume_name:/data -v $(pwd):/backup alpine tar czf /backup/$BACKUP_FILE -C /data .
echo "Backup created: $BACKUP_FILE"
```

**Restore script (restore.sh):**

```bash
docker run --rm -v volume_name:/data -v $(pwd):/backup alpine tar xzf /backup/$BACKUP_FILE -C /data
echo "Restoration completed from: $BACKUP_FILE"
```

Schedule with cron for regular backups.

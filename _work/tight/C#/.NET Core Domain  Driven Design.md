## What is Domain-Driven Design (DDD)?

**DDD** centers software design on a **domain model** reflecting the business problem. Structure code around **Entities**, **Value Objects**, **Aggregates**, **Repositories**, and **Services**, keeping domain logic separate from infrastructure.

## What are Entities?

An **Entity** is defined by a unique **identity (ID)**, not attributes. Its lifecycle and state changes matter.

Example: `Customer` with `CustomerId` — address and name change over time.

```csharp
public class Customer
{
    public Guid CustomerId { get; private set; }
    public string Name { get; private set; }
    public string Email { get; private set; }
    public Address Address { get; private set; }

    public Customer(string name, string email, Address address)
    {
        CustomerId = Guid.NewGuid();
        Name = name;
        Email = email;
        Address = address;
    }

    public void UpdateAddress(Address newAddress)
    {
        Address = newAddress;
    }
}
```

## What are Value Objects?

A **Value Object** is **immutable**, has **no identity**, and is defined by its attributes (e.g., `Address`, `Money`).

```csharp
public class Address
{
    public string Street { get; private set; }
    public string City { get; private set; }
    public string ZipCode { get; private set; }

    public Address(string street, string city, string zipCode)
    {
        Street = street;
        City = city;
        ZipCode = zipCode;
    }

    // Two addresses are equal if all attributes match.
    public override bool Equals(object obj)
    {
        if (obj is Address address)
        {
            return Street == address.Street && City == address.City && ZipCode == address.ZipCode;
        }
        return false;
    }

    public override int GetHashCode() => (Street, City, ZipCode).GetHashCode();
}
```

## What are Aggregates?

An **Aggregate** is a cluster of entities and value objects treated as one unit for data changes. The **Aggregate Root** controls access.

Example: `Order` (root) contains `OrderItem` entities and references `Customer`.

```csharp
public class Order
{
    public Guid OrderId { get; private set; }
    public Customer Customer { get; private set; }
    public List<OrderItem> OrderItems { get; private set; }
    public decimal TotalAmount => OrderItems.Sum(item => item.Price * item.Quantity);

    public Order(Customer customer)
    {
        OrderId = Guid.NewGuid();
        Customer = customer;
        OrderItems = new List<OrderItem>();
    }

    public void AddItem(OrderItem item) => OrderItems.Add(item);
    public void RemoveItem(OrderItem item) => OrderItems.Remove(item);
}

public class OrderItem
{
    public Guid ProductId { get; private set; }
    public string ProductName { get; private set; }
    public int Quantity { get; private set; }
    public decimal Price { get; private set; }

    public OrderItem(Guid productId, string productName, int quantity, decimal price)
    {
        ProductId = productId;
        ProductName = productName;
        Quantity = quantity;
        Price = price;
    }
}
```

## What are Repositories?

**Repositories** abstract data access and persist aggregates, keeping domain entities isolated from persistence.

```csharp
public interface IOrderRepository
{
    Order GetOrderById(Guid orderId);
    void AddOrder(Order order);
    void SaveChanges();
}

public class OrderRepository : IOrderRepository
{
    private readonly DbContext _context;

    public OrderRepository(DbContext context) => _context = context;

    public Order GetOrderById(Guid orderId)
    {
        return _context.Orders.Include(o => o.OrderItems).FirstOrDefault(o => o.OrderId == orderId);
    }

    public void AddOrder(Order order) => _context.Orders.Add(order);
    public void SaveChanges() => _context.SaveChanges();
}
```

## What are Domain Services?

**Domain Services** hold logic that doesn't fit in an entity or value object — operations spanning multiple entities/aggregates.

```csharp
public class DiscountService
{
    public decimal CalculateDiscount(Order order)
    {
        if (order.TotalAmount > 1000)
            return order.TotalAmount * 0.1m; // 10% discount for orders over 1000
        return 0;
    }
}
```

## What are Application Services?

**Application Services** orchestrate use cases — entry points coordinating aggregates, repositories, and domain services.

```csharp
public class OrderService
{
    private readonly IOrderRepository _orderRepository;
    private readonly DiscountService _discountService;

    public OrderService(IOrderRepository orderRepository, DiscountService discountService)
    {
        _orderRepository = orderRepository;
        _discountService = discountService;
    }

    public void CreateNewOrder(Customer customer)
    {
        var order = new Order(customer);
        _orderRepository.AddOrder(order);
        _orderRepository.SaveChanges();
    }

    public void AddItemToOrder(Guid orderId, OrderItem orderItem)
    {
        var order = _orderRepository.GetOrderById(orderId);
        order.AddItem(orderItem);
        _orderRepository.SaveChanges();
    }

    public decimal GetOrderDiscount(Guid orderId)
    {
        var order = _orderRepository.GetOrderById(orderId);
        return _discountService.CalculateDiscount(order);
    }
}
```

## What are Domain Events?

**Domain Events** capture significant domain occurrences, decoupling reactions (inventory, email, shipping) from aggregate logic.

```csharp
public class OrderPlacedEvent
{
    public Order Order { get; }
    public OrderPlacedEvent(Order order) => Order = order;
}
```

With richer payload:

```csharp
public class OrderPlacedEvent
{
    public Guid OrderId { get; }
    public Guid CustomerId { get; }
    public DateTime OrderDate { get; }

    public OrderPlacedEvent(Guid orderId, Guid customerId, DateTime orderDate)
    {
        OrderId = orderId;
        CustomerId = customerId;
        OrderDate = orderDate;
    }
}
```

## What is a Bounded Context?

A **Bounded Context** defines a boundary where a specific domain model applies. Example: ordering (customer, order, products) is separate from shipping or inventory contexts.

**Typical .NET Core DDD layout:**

- **Order Aggregate** — `Order` + `OrderItem` entities
- **OrderService** — orchestrates create/add operations
- **OrderRepository** — persistence
- **DiscountService** — business rules
- **Domain Events** — notify on key events (e.g., order placed)

## How do you implement Domain Events in .NET Core?

**Steps:** define event → raise in aggregate → create handlers → dispatch.

**Raise events in aggregate:**

```csharp
public class Order
{
    public Guid OrderId { get; private set; }
    public Guid CustomerId { get; private set; }
    public List<OrderItem> OrderItems { get; private set; }
    public DateTime OrderDate { get; private set; }
    private List<object> _domainEvents = new List<object>();
    public IReadOnlyList<object> DomainEvents => _domainEvents;

    public Order(Guid customerId)
    {
        OrderId = Guid.NewGuid();
        CustomerId = customerId;
        OrderDate = DateTime.Now;
        OrderItems = new List<OrderItem>();
    }

    public void AddItem(OrderItem item) => OrderItems.Add(item);

    public void PlaceOrder()
    {
        var orderPlacedEvent = new OrderPlacedEvent(OrderId, CustomerId, OrderDate);
        _domainEvents.Add(orderPlacedEvent);
    }

    public void ClearDomainEvents() => _domainEvents.Clear();
}
```

**Event handlers:**

```csharp
public class InventoryHandler
{
    public void Handle(OrderPlacedEvent domainEvent)
    {
        Console.WriteLine($"Adjusting inventory for Order ID: {domainEvent.OrderId}");
    }
}

public class EmailNotificationHandler
{
    public void Handle(OrderPlacedEvent domainEvent)
    {
        Console.WriteLine($"Sending notification to Customer ID: {domainEvent.CustomerId}");
    }
}
```

**Dispatcher:**

```csharp
public class DomainEventDispatcher
{
    private readonly IEnumerable<object> _handlers;

    public DomainEventDispatcher(IEnumerable<object> handlers) => _handlers = handlers;

    public void Dispatch(object domainEvent)
    {
        foreach (var handler in _handlers)
        {
            var method = handler.GetType().GetMethod("Handle", new[] { domainEvent.GetType() });
            method?.Invoke(handler, new[] { domainEvent });
        }
    }
}
```

**Application layer:**

```csharp
public class OrderService
{
    private readonly IOrderRepository _orderRepository;
    private readonly DomainEventDispatcher _domainEventDispatcher;

    public OrderService(IOrderRepository orderRepository, DomainEventDispatcher domainEventDispatcher)
    {
        _orderRepository = orderRepository;
        _domainEventDispatcher = domainEventDispatcher;
    }

    public void PlaceOrder(Order order)
    {
        order.PlaceOrder();
        _orderRepository.Save(order);
        foreach (var domainEvent in order.DomainEvents)
        {
            _domainEventDispatcher.Dispatch(domainEvent);
        }
        order.ClearDomainEvents();
    }
}
```

**DI registration:**

```csharp
public void ConfigureServices(IServiceCollection services)
{
    services.AddScoped<InventoryHandler>();
    services.AddScoped<EmailNotificationHandler>();
    services.AddScoped<DomainEventDispatcher>(provider =>
    {
        var handlers = new List<object>
        {
            provider.GetService<InventoryHandler>(),
            provider.GetService<EmailNotificationHandler>()
        };
        return new DomainEventDispatcher(handlers);
    });
}
```

**Workflow:** customer places order → `PlaceOrder` raises `OrderPlacedEvent` → dispatcher invokes handlers → events cleared.

## How do DDD, Domain Events, and CQRS work together?

**CQRS** separates **write** (commands) from **read** (queries) models. Combined with DDD and domain events, side effects stay decoupled and read/write paths scale independently.

**Command (write side):**

```csharp
public class PlaceOrderCommand
{
    public Guid CustomerId { get; set; }
    public List<OrderItem> Items { get; set; }
}

public class PlaceOrderCommandHandler
{
    private readonly IOrderRepository _orderRepository;
    private readonly DomainEventDispatcher _eventDispatcher;

    public PlaceOrderCommandHandler(IOrderRepository orderRepository, DomainEventDispatcher eventDispatcher)
    {
        _orderRepository = orderRepository;
        _eventDispatcher = eventDispatcher;
    }

    public void Handle(PlaceOrderCommand command)
    {
        var order = new Order(command.CustomerId);
        foreach (var item in command.Items)
        {
            order.AddItem(item);
        }
        order.PlaceOrder();
        _orderRepository.Save(order);
        foreach (var domainEvent in order.DomainEvents)
        {
            _eventDispatcher.Dispatch(domainEvent);
        }
        order.ClearDomainEvents();
    }
}
```

**Event handlers:**

```csharp
public class InventoryUpdateHandler
{
    public void Handle(OrderPlacedEvent domainEvent)
    {
        Console.WriteLine($"Updating inventory for Order ID: {domainEvent.OrderId}");
    }
}

public class EmailNotificationHandler
{
    public void Handle(OrderPlacedEvent domainEvent)
    {
        Console.WriteLine($"Sending confirmation email to Customer ID: {domainEvent.CustomerId}");
    }
}
```

**Query (read side):**

```csharp
public class OrderQueryModel
{
    public Guid OrderId { get; set; }
    public Guid CustomerId { get; set; }
    public DateTime OrderDate { get; set; }
    public List<OrderItem> Items { get; set; }
}

public class GetOrderByIdQuery
{
    public Guid OrderId { get; }
    public GetOrderByIdQuery(Guid orderId) => OrderId = orderId;
}

public class OrderQueryHandler
{
    private readonly IOrderQueryRepository _queryRepository;

    public OrderQueryHandler(IOrderQueryRepository queryRepository) => _queryRepository = queryRepository;

    public OrderQueryModel Handle(GetOrderByIdQuery query)
    {
        return _queryRepository.GetById(query.OrderId);
    }
}
```

**CQRS DI wiring:**

```csharp
public void ConfigureServices(IServiceCollection services)
{
    services.AddScoped<PlaceOrderCommandHandler>();
    services.AddScoped<InventoryUpdateHandler>();
    services.AddScoped<EmailNotificationHandler>();
    services.AddScoped<DomainEventDispatcher>(provider =>
    {
        var handlers = new List<object>
        {
            provider.GetService<InventoryUpdateHandler>(),
            provider.GetService<EmailNotificationHandler>()
        };
        return new DomainEventDispatcher(handlers);
    });
    services.AddScoped<OrderQueryHandler>();
}
```

**Execution flow:**

1. `PlaceOrderCommand` → `PlaceOrderCommandHandler` creates aggregate, raises `OrderPlacedEvent`
2. Dispatcher routes to `InventoryUpdateHandler` and `EmailNotificationHandler`
3. Read model updated separately; `OrderQueryHandler` serves queries from optimized read store

**Benefits:** decoupled write/read models, clean aggregates, modular side effects, improved scalability and separation of concerns. Optional **Event Sourcing** stores event sequences instead of current state.
